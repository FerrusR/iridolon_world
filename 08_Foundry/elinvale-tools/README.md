# Elinvale tools (`elinvale-tools`) — модуль Foundry VTT (PF2e)

**Единый модуль-контейнер** для всего хоумбрю мира. Сейчас в нём два пака — **deities**
(пятёрка богов) и **items** (предметы-реликвии). В будущем сюда же добавляются новые паки
(монстры, журналы, макросы) — отдельный модуль на каждое мелкое изменение плодить не нужно.

Пак **deities**: Темпус (Время/Судьба), Вирелла (Жизнь), Морана (Смерть), Магнус
(Справедливость), Лире (Удача). Совместимо с Foundry **v14** и системой **PF2e 8.x**.

Каждый бог заполнен по канону волта: сфера, эдикты, анафема, кто поклоняется, а также
механические поля PF2e — Divine Font, Divine Skill, Divine Attribute, Favored Weapon и
домены (primary + alternate). Текст — player-facing.

Пак **items** — реликвии PC (по одной на игрока) с их Gift 1 и seed-свойствами.
Канон механики — в волте: `06_Mechanics/Реликвии — хоумрул.md`. Подробнее ниже.

Паки **bestiary** («Бестиарий Элинваля», Actor) и **gm-items** («Элинваль — мастерское»,
Item) — **только для GM** (`PLAYER: NONE`), чтобы не светить игрокам спойлеры. Сейчас там
бой у сердца дракона (Глава 3): Дарио, его мертвецы, сердце-hazard, толстый корень, два
рубщика и эффект «Переполняющая сила». Постановка — `05_Campaign/Арка 1/Глава 3 - бой у сердца.md`.

Пак **gm-macros** («Элинваль — макросы ГМ», Macro, только GM) — макрос «Остановка времени».

**Визуал боя у сердца** (код в `esmodules/`, выкатка `./scripts/deploy.sh --no-build`):
- «Переполняющая сила» светит янтарём сама (правило `TokenLight`; заменяет свет токена, в т.ч. факел,
  пока висит эффект). `overflowing-power.mjs` вешает над токеном (правый верхний угол) янтарную руну JB2A (`Rune02Loop`,
  у каждого актёра своя) через Sequencer и снимает её вместе с эффектом. Нужны `sequencer` и
  `jb2a_patreon`; без них остаётся только свет.
- `time-stop.mjs` — тумблер FXMaster (обесцвечивание + янтарь + зависшие искры) на **открытой у ГМ**
  сцене, не на активной. Макрос из пака или `game.modules.get("elinvale-tools").api.toggleTimeStop()`.

## Установка и выкатка

### Mythic — правила стола

`esmodules/mythic-rules.mjs` подключает принятые правила из `06_Mechanics/Mythic — хоумрул.md`.
Настройка **Mythic: правила Элинваля** включена по умолчанию; изменение требует перезагрузки мира.
Проверено по установленному исходному коду **PF2e 8.6.0**.

- Меню сообщения: **Rewrite Fate (1 Mythic Point)** для skill checks и saving throws;
  **Обычный переброс (1 Mythic Point)** для checks без повышения proficiency, с обязательным новым результатом.
  Списание MP, защита от повторного клика, сохранение исходных модификаторов/MAP и приватности броска.
- Mythic Resilience сохраняет повышение save только против немифического источника.
  Остальные AdjustDegreeOfSuccess не меняются. Calling распознаётся как мифический источник
  даже при 0 оставшихся MP. Актёры и Item sources в базе не переписываются.
- Anathema и получение MP остаются под контролем GM.

`esmodules/mythic-feats.mjs` добавляет в штатное окно модификаторов переключатели
**Ears That Hear the Truth — 1 Mythic Point** и **Arms That Cut the Waves — 1 Mythic Point**.
При наличии фита и хотя бы 1 MP окно открывается даже для быстрых бросков:

- Ears: **Perception initiative** и действие **Sense Motive**.
- Arms: действие **Swim** через Athletics.

Фит должен быть на листе персонажа. Переключатель по умолчанию выключен; при включении
proficiency заменяется на `level + 10` только для этого броска. Остальные модификаторы,
DC, fortune/misfortune и скрытый режим сохраняются. Подтверждение списывает 1 MP до
броска; закрытие окна или выключенный переключатель ничего не списывают. При ошибке
до завершения броска MP возвращается. Листы и proficiency персонажа не переписываются.
Поддерживаются броски владельца и GM; штатный обработчик PF2e обновляет инициативу в tracker.

Для Sense Motive и Swim запускай **соответствующее действие**, а не общий Perception
или Athletics check: по общему броску невозможно определить применение фита.
Для инициативы через Stealth переключателя Ears нет. Продление дыхания из Arms на
10 раундов остаётся ручным применением за 1 MP; этот эффект не требует броска.

Вручную созданная Resilience распознаётся по slug `mythic-resilience` (включая суффиксы),
официальному source или английскому имени. Для другой способности: Item flag
`elinvale-tools.mythicResilience = true`. Нужны уже существующие AdjustDegreeOfSuccess rules.
Если save бросается прямо с листа без источника, автоматический обход определить нельзя:
использовать кнопку save из карточки заклинания/способности либо проверить результат вручную.

Локальные проверки: `node --test scripts/test-mythic-rules.mjs scripts/test-mythic-feats.mjs`.
После выкатки проверить в игре как GM и игроком: обычный Strike с MAP, flat check,
Rewrite Fate для skill/save, save NPC с Resilience от мифического и немифического caster.
Также: Ears для Perception initiative и secret Sense Motive, Arms для Swim, отмену окна,
выключение переключателя и недоступность этих опций для других checks.
Выкатка скрипта: `./scripts/deploy.sh --no-build`, затем обновить страницы всех клиентов.

### Пассивный монитор бросков

`esmodules/roll-monitor.mjs` + `roll-monitor-core.mjs`: включён по умолчанию, настройка и
кнопка **Монитор бросков → Открыть отчёт** доступны только GM в Module Settings.
Скрипт не блокирует и не исправляет броски, не замораживает функции и не делает дополнительных
бросков. Игрокам не добавляет интерфейс, сообщения или уведомления.

- На клиентах игроков отслеживает замену RNG, основного fulfillment handler, методов
  DiceTerm/Die и Roll, а также изменение конфигурации способа броска. Сравнивает ссылки
  на функции, не вызывает RNG для проверки. Изменения между загрузкой скрипта и окончанием
  ready сохраняет как `startup-change`: это диагностика, включая штатные правки модулей.
- Для обычных checks сравнивает dice/formula/total после `evaluate` и перед `toMessage`.
  Изменённый результат публикуется как обычно; GM получает `check-changed`. Fortune/misfortune,
  Hero/Mythic rerolls и заранее выбранные substitutions сами по себе тревогу не вызывают.
  Damage, checks без dice и старые десериализованные rolls эта проверка не оценивает.
- Отчёты отправляет **только подключённым GM** через Foundry 14 `recipients`. Отправитель
  определяется по ID, который сервер добавляет к событию, а не по полю в отчёте игрока.
  До подтверждения GM событие повторяется раз в 5 секунд; буфер клиента — до 40 записей.
  Status обновляется раз в минуту, содержит текущие fingerprints и счётчик вытесненных событий.
- GM видит краткое уведомление и журнал последних 300 событий с экспортом JSON.
  Журнал хранится в **localStorage этого браузера GM**, отдельно для мира и пользователя;
  не в world settings, flags или чате. При очистке данных браузера журнал пропадёт.
  Данные API: `game.modules.get("elinvale-tools").api.getRollMonitorReport()`;
  окно: `.api.openRollMonitor()`. После отключения мониторинга перезагрузить клиентов.

Событие сообщает технический факт и требует проверки: легальный модуль тоже может менять
код или результат. Хорошие броски и отсутствие отчёта не считаются свидетельством вмешательства.
Нет защиты от игрока, который отключил/подделал монитор, от всех изменений до его загрузки,
от коротких подмен между проверками или от полностью сфабрикованных правдоподобных rolls.
Observer может быть обойдён при публикации через другой путь, минуя `Roll.toMessage`.
Код и трафик можно найти при целенаправленном осмотре браузера.

Локальные проверки: `node --test scripts/test-roll-monitor.mjs scripts/test-mythic-rules.mjs scripts/test-mythic-feats.mjs`.
Перед использованием проверить в отдельном тестовом мире с двумя клиентами: обычный/secret
check, fortune/misfortune, Hero/Mythic reroll и substitution; затем безопасную замену функции
с тем же поведением и восстановление оригинала. Броски должны продолжаться, уведомление
и отчёт должны появляться только у GM. Проверить повторную доставку при переподключении GM.
Для интерфейсного кода достаточно `./scripts/deploy.sh --no-build` и перезагрузки всех клиентов.

**Быстрая проверка в Foundry:** GM открывает отчёт и нажимает **Самопроверка**.
Ожидаются четыре PASS: замена функции, восстановление, обычный check без события и
изменённый check без исправления. Проверка использует изолированный Roll и `create:false`,
не меняет общие функции и не публикует сообщений. Она проверяет логику и текущий Foundry API,
но не доставку с клиента игрока.

**Проверка доставки:** открыть второй браузер/приватное окно, войти тестовым игроком.
В окне GM убедиться, что отчёт показывает свежий status этого пользователя. В консоли
браузера **тестового игрока** выполнить безопасную временную обёртку с тем же поведением:

```js
(() => {
  const method = CONFIG.Dice.fulfillment.methods.mersenne;
  const original = method.handler;
  const probe = function (...args) { return original.apply(this, args); };
  method.handler = probe;
  setTimeout(() => {
    if (method.handler === probe) method.handler = original;
  }, 4000);
})();
```

Держать окно игрока открытым и активным хотя бы 5 секунд, затем заново открыть отчёт GM.
Ожидаются два `function-change` от тестового пользователя: установка обёртки и восстановление.
У GM будет уведомление (повторные уведомления ограничены по частоте), у игрока — никаких.
Затем сделать обычный check: бросок проходит как прежде, новых `check-changed` нет.
Для проверки повторной доставки закрыть вкладку GM, повторить тест игроком и снова открыть
GM: буферизированные события должны дойти после подключения. Не считать успех локальной
самопроверки подтверждением этой сетевой проверки.

Компендиум — это база LevelDB, её нельзя редактировать руками: её надо **скомпилировать**
официальным CLI. Нужен установленный Node.js.

**Среда агента:** ограничение сборки относилось к песочнице Claude (npm/pip заблокированы).
В песочнице **Codex** сборка с уже установленным `@foundryvtt/foundryvtt-cli` работает:
`node scripts/build.mjs` из папки модуля. Проверено 2026-10-21 в отдельной временной копии:
собраны 5 богов и 13 предметов. Установка новых зависимостей этим не проверялась.
Сборка в волте и выкатка в работающий Foundry — отдельные действия; для проверки без
изменения `packs/` волта собирай во временной копии.

### Быстрый путь — `scripts/deploy.sh` (рекомендуется)

Один скрипт делает всё за вызов: пересобирает паки, останавливает Foundry, сносит старую
копию модуля, кладёт свежую (`rsync --delete`, без build-обвязки) и запускает Foundry
обратно. Foundry поднимается назад даже если шаг упал (trap на выходе).

```bash
cd elinvale-tools
npm install @foundryvtt/foundryvtt-cli   # только один раз (CLI нужен для сборки)
./scripts/deploy.sh                       # полный цикл: build → stop → выкатка → start
```

Флаги и настройки:

- `./scripts/deploy.sh --no-build` — выкатить уже собранное, без пересборки.
- `FOUNDRY_MODULES=/путь/к/Data/modules ./scripts/deploy.sh` — переопределить путь к модулям.
- Foundry-сервис — **user-unit** (`systemctl --user foundry.service`), sudo не нужен.

После первой установки в Foundry: **Game Settings → Manage Modules** — включить
«Elinvale tools». Дальше правки исходников выкатываются одним `./scripts/deploy.sh`.

### Вручную (что `deploy.sh` делает под капотом)

```bash
cd elinvale-tools
node scripts/build.mjs                       # пересобирает packs/ из src/ (сам чистит старое)
cd ..

# Foundry должен быть ЗАКРЫТ (или мир не запущен) — иначе LevelDB держит паки
# открытыми/залоченными, и копия либо не применится, либо затрётся при выходе.
systemctl --user stop foundry.service
rm -rf /home/ferrus/foundrydata/Data/modules/elinvale-tools   # снести старую копию ЦЕЛИКОМ
cp -r elinvale-tools /home/ferrus/foundrydata/Data/modules/   # положить свежую
systemctl --user start foundry.service
```

> ### ⚠️ Почему обязательно `rm -rf` перед копированием
>
> Компендиум — это база **LevelDB**, а не один файл: каждый раз, когда Foundry открывает
> мир, он делает компакцию и дописывает в папку пака новые файлы с растущими номерами
> (`000007.ldb`, `MANIFEST-000006`, `LOG.old`, …). `cp -r` поверх существующей папки
> **сливает**: одноимённые файлы перезатирает, а осиротевшие от прошлых компакций —
> **оставляет**. Отсюда два симптома, которые ты и видел:
>
> - **Файлов в `packs/*` становится всё больше** — старьё не удаляется.
> - **Правки «не применяются»** — `CURRENT` в назначении может указывать на старый
>   `MANIFEST`, ссылающийся на устаревшие `.ldb`; смешивать файлы двух разных инстансов
>   LevelDB в одной папке — неопределённое поведение (то свежие данные, то старые).
>
> `build.mjs` свою сторону чистит сам (`rmSync(destDir)` перед сборкой), так что расти
> может только **назначение** в `Data/modules/`. Лечение — сносить его перед копией.
>
> **Альтернатива одной командой** (без ручного `rm`): `rsync` с `--delete` синхронизирует
> назначение с источником, удаляя лишнее:
>
> ```bash
> rsync -a --delete elinvale-tools/ /home/ferrus/foundrydata/Data/modules/elinvale-tools/
> ```

**Добавить новое в модуль позже** (предметы, монстры, журналы, макросы): в `module.json`
допиши запись в массив `packs`, создай папку `src/<имя-пака>/` с JSON-документами и снова
прогони `node scripts/build.mjs`. Всё копится в одном модуле `elinvale-tools`.

## После установки: как игроки выбирают бога

1. **Compendium Browser** (иконка книги на боковой панели) → вкладка **Deities**. Чтобы
   боги там появились: в браузере **Settings → Sources** отметь источник «Боги Элинваля».
   Без этого браузер их не индексирует.
2. На листе персонажа: вкладка **Details** → поле **Deity** — перетащить бога из
   компендиума. Домены, шрифт, оружие и навык подтянутся автоматически.

## Реликвии PC — как это устроено

Пять реликвий, по одной на игрока. Общая схема одинакова:

- **Реликвия-предмет** (weapon / equipment). Носимые/телесные реликвии — invested
  worn equipment (инвестируешь → дар и seed включаются; снял/разинвестировал — гаснут).
  Пистолеты — weapon (дар активен, пока в руках).
- **`GrantItem`** на реликвии: пока предмет экипирован/инвестирован, соответствующий
  **дар-действие** сам появляется на вкладке **Actions**. Снял предмет — действие исчезает
  (rule elements физических предметов подавляются, когда предмет не экипирован/не
  инвестирован).
- **Дар-действие** (type `action`) несёт `actionType` (action/reaction), `frequency`
  once per hour и `selfEffect` → при использовании автоматически вешает
  **кулдаун-эффект «Дар реликвии — кулдаун (1 ч)»** (общий на все дары; тикает игровым
  временем). В описании — только механика + кликабельные ссылки (`@Check`, `@Damage`,
  `@UUID` на эффекты для перетаскивания). Флейвор Ferrus дописывает сам.
- **Seed-свойства** с бонусом к навыку зашиты как `FlatModifier` (item bonus) прямо на
  реликвии — применяются, пока инвестировано. Рост до +2 на relic 9 — поднять `value`
  вручную. Seed'ы-флейвор (осечки в чужой руке, «жуть в зеркалах») не автоматизированы.

**Кликабельно из карточки действия** (посылаешь действие в чат): `@Template` — кнопка
поставить шаблон (Frost Slick), `@Check` — сейв, `@Damage` — ролл урона/лечения (Rewind
даёт healing-ролл с кнопкой «apply healing» = предотвращённый урон), `@UUID` — перетащить
эффект (panache, resistance, откат, кулдаун).

Что **не** автоматизировано намеренно (отыгрыш вручную): применение difficult terrain и
prone, перезарядка, вражеские сейвы, перемещение, вражеский перебросок misfortune.

| PC | Реликвия (файл) | Дар (Gift 1) | Авто-механика |
|---|---|---|---|
| Тео (Starlord) | Парные пистолеты · `starlord-pistols.json` | Ледяная наледь / *Frost Slick* (`◆◆`, 1/h) | GrantItem→action, кулдаун, **@Template** (10-ft burst) + `@Check[reflex]` + `@Damage[1d6[cold]]` |
| Артур | Золотой шар · `arthur-orb.json` | Отмотка удара / *Rewind the Blow* (`⤾` reaction, 1/h) | +1 item Medicine (Treat Wounds/Battle Medicine), GrantItem→reaction, кулдаун, **@Damage[2d8[healing]]** (кнопка apply healing = предотвращение) |
| Фейт | Книга Судеб · `fate-book.json` | Дурное предзнаменование / *Foretold Misfortune* (`⤾` reaction, 1/h) | +1 item Occultism, GrantItem→reaction, кулдаун, эффект-**откат** (RollTwice keep lower на след. attack/save) |
| Кхар'Хадаг | Мутации · `khar-hadag-mutations.json` | Ответная мутация / *Answering Mutation* (`⤾` reaction, 1/h) | +1 item Survival, GrantItem→reaction, кулдаун, эффект-**resistance 5** (ChoiceSet выбор типа, до конца след. хода) |

**Общие эффекты** (`effect-*.json`): кулдаун-эффект 1 ч (общий), resistance-эффект
Ответной мутации, откат-эффект Дурного предзнаменования, Effect: Panache, эффект «Слышащий кровь». Дар-действия и
эффекты лежат в том же паке `items` — их можно и перетаскивать вручную, если GrantItem
почему-то не сработал. Panache — self-contained дубликат: если finisher'ы завязаны на
встроенный тумблер свашбаклера, используй его.

> **Проверить в Foundry после сборки:** что granted-действие появляется при
> equip/invest и исчезает при снятии; что `selfEffect` вешает кулдаун по клику на
> действие; что ChoiceSet Ответной мутации спрашивает тип урона; что `frequency`
> (`per: "PT1H"`) и RollTwice-откат отрабатывают. Рост даров по сюжету (g2/g3/grand) пока
> не вшит — добавим rule elements, когда линии дойдут.

## Награды Главы 3 — Ветвь Древа и «Сила жизни»

Канон механики — `06_Mechanics/Ветвь Древа.md` и Глава 3 § Сухое русло и лесное озеро.

- **Ветвь Древа** (`tree-branch.json`, equipment, held in 1 hand, L). Активация описана в
  тексте предмета в формате `Activate— ◆◆ (manipulate)` + `Frequency once per day`, поэтому
  **PF2e Item Activations** сам создаёт действие «Activation: Укрытие Древа» с счётчиком 1/день
  (сбрасывается на Rest for the Night). В карточке действия — ссылка на эффект. Флейвор после блока
  Activate не писать: Item Activations копирует в действие всё, что идёт после него.
  Скрытое свойство («узнаёт хозяйку») в Foundry не внесено — оно только в волте.
- **Укрытие Древа** (`effect-tree-ward.json`) — sanctuary на 1 минуту. Перетаскивать **с
  карточки активации** (или с действия на листе владельца) на токен цели: PF2e запоминает
  происхождение эффекта, и formula-badge `@item.origin.system.attributes.classOrSpellDC.value`
  считает DC владельца ветви. DC виден на значке эффекта и в чате; в описании эффекта кнопка
  спаса Воли для атакующего (`@Check[will|dc:resolve(@item.badge.value)]`). Если тянуть из
  компендиума, DC возьмётся у того, на кого повесили.
- **Сила жизни** (`effect-summer-in-blood.json`, slug `elinvale-summer-in-blood`) — resistance
  void 2, без срока; ГМ вешает искупавшимся и снимает на выходе из леса.
- **Прилив** (`effect-summer-surge.json`) — TempHP 3, длительность encounter. Выдаёт его
  `esmodules/summer-in-blood.mjs` на хуке `combatStart`, **только пока включён тумблер**
  Game Settings → Module Settings → «Сила жизни: прилив в начале боя» (world, только ГМ,
  по умолчанию выключен). Включён — в начале боя прилив получает каждый участник с «Силой
  жизни»; выключен — хук ничего не делает. Включать, когда партия получила баф, выключать на
  выходе из леса. С хотбара: макрос `game.modules.get("elinvale-tools").api.toggleSummerSurge()`
  (ещё есть `setSummerSurge(true|false)` и `isSummerSurgeActive()`). В конце боя PF2e снимает
  прилив вместе с остатком временных HP. Хук работает у ГМ: начинать бой должен ГМ.

> **Проверить в Foundry после выкатки:** ветвь в руке → на листе появилось действие с
> 1/день; «Use» → карточка с DC; перетащить «Укрытие Древа» с карточки на союзника →
> на значке DC владельца; кнопка Will в эффекте бросает против него. Повесить «Силу
> жизни», включить тумблер → Begin Combat → у носителя 3 temp HP и эффект прилива; End
> Combat → прилив ушёл; выключить тумблер → новый бой без прилива.

## Скрыть богов Paizo (не удаляя)

Богов Paizo штатно удалить нельзя (системные паки залочены), да и не нужно — достаточно
скрыть их от игроков:

1. **Compendium Browser → Settings → Sources** — снять галки с источников Paizo

   **Configure Ownership** → роли *Player* поставить **None**. GM видит, игроки — нет.

## Музыкальный пульт (список «ситуация → трек»)

Окно с записями вида «Драка с волками → *Dancing with the wolves*», сгруппированными
в папки (арка → глава). Кнопка ▶ у записи **глушит всю играющую музыку и включает её трек**;
**Shift+▶** запускает поверх, ничего не глуша (для эмбиента). Кнопка **Стоп** в шапке
останавливает всё.

**Как открыть** (что удобнее):

- кнопка **«Пульт»** в шапке вкладки *Playlists*;
- горячая клавиша **Ctrl+M** (меняется в *Configure Controls*);
- **Game Settings → Module Settings → Музыкальный пульт → Открыть пульт**;
- макрос на панели: `game.modules.get("elinvale-tools").api.openMusicCues()`.

**Как вести список:**

- `+` — новая запись, `папка+` — новая папка (папки вкладываются друг в друга);
- трек берётся **перетаскиванием из вкладки Playlists**: бросить на строку — трек привяжется
  к ней; бросить на папку — внутри создастся новая запись с названием трека;
- перетащить можно и **плейлист целиком** — тогда запись запускает его (`playAll`);
- строки перетаскиваются за любое место: на другую строку — встать перед ней, на папку — лечь внутрь;
- поле «Ситуация» правится прямо в строке, сохраняется по Enter или потере фокуса;
- кнопка `</>` — экспорт/импорт всего списка JSON-ом (бэкап, перенос в другой мир).

**Где лежат данные.** В мире, в настройке `elinvale-tools.musicCues` (не в компендиуме).
Видит и правит только GM. Записи переживают выкатку модуля; бэкап — через кнопку JSON.

**Что стоит знать:**

- «Стоп» останавливает только плейлисты. Звуки, расставленные на сцене (Ambient Sounds),
  продолжают играть — их глушат на слое звука.
- Что будет, когда трек кончится, решают его собственные настройки: с включённым повтором
  зациклится, в последовательном плейлисте пойдёт следующий трек.
- Если трек удалили из плейлистов, запись подсветится предупреждением, а не молча промолчит.

**Код.** `esmodules/music-cues.mjs` + `styles/music-cues.css`, подключены в `module.json`
(`esmodules`, `styles`). Компендиум-паки тут ни при чём: после правки кода достаточно
`./scripts/deploy.sh --no-build` и F5 в браузере. `deploy.sh` не копирует `scripts/`, `src/`
и `package*.json` — поэтому код интерфейса лежит именно в `esmodules/`, а не в `scripts/`.
