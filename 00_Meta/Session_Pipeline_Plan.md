# Пайплайн обработки сессий — high-level план

> Запись сессии в Discord → транскрипт → саммари, решения и TODO в волте.
> Запуск руками, одним скриптом, после каждой сессии.

## Обзор потока

```
Craig (Discord) ──скачал zip──▶ [1] Препроцессинг (ffmpeg)
                                    │  дорожки → чанки речи + карта таймстемпов
                                    ▼
                               [2] AssemblyAI (language_code=ru)
                                    │  транскрипт каждой дорожки
                                    ▼
                               [3] Merge: единый хронологический транскрипт
                                    │  [чч:мм:сс] Игрок (Персонаж): реплика
                                    ▼
                               [4] Anthropic Batches API (Sonnet, −50%)
                                    │  map (по чанкам) → reduce (итог)
                                    ▼
                               [5] Запись в волт + git commit
```

## Этапы подробнее

### 1. Запись и препроцессинг
- **Craig** пишет **отдельную дорожку на игрока**, все дорожки синхронизированы. Качаем **FLAC multi-track** — в архиве есть `info.txt` с соответствием дорожка → Discord-ник.
- Diarization **не нужна**: атрибуция «кто говорит» бесплатно следует из дорожек.
- **ffmpeg** на каждой дорожке: нормализация громкости + вырезание тишины (`silencedetect`). Дорожка игрока — это на ~80% тишина; AssemblyAI биллит по длительности аудио, так что вырезание тишины режет стоимость STT примерно в 4-5 раз. Оффсеты вырезанных кусков сохраняем в JSON, чтобы восстановить абсолютные таймстемпы.
- Маппинг ник → игрок → персонаж держим в конфиге (`players.yaml`).

### 2. Транскрипция — AssemblyAI
- Модель **Universal-2**, `language_code: "ru"` (русский в группе высокой точности, WER ≤10%).
- **`word_boost` / custom vocabulary**: скармливаем список имён собственных мира, автоматически собранный из имён файлов волта (NPC, локации, фракции, термины). Это главный рычаг качества — без него уникальные имена будут искажаться.
- SDK: `pip install assemblyai`. Загружаем файлы напрямую (FLAC принимает), поллим до готовности.

### 3. Merge
- Utterances всех дорожек сливаем по восстановленным абсолютным таймстемпам → один markdown-файл: `[00:42:17] Antony (Ferrus, GM): ...`.
- Полный транскрипт сохраняем: `05_Campaign/Transcripts/Session_NN_transcript.md`.

### 4. LLM-обработка — Anthropic Batches API
- **Почему Batches**: −50% к цене токенов, результат асинхронно (обычно минуты, максимум 24 ч) — для пост-обработки идеально.
- Транскрипт 4-часовой сессии — порядка 100-200k токенов. Схема **map-reduce**:
  - *map*: транскрипт бьём на чанки (~30-50k токенов, по границам сцен/пауз), каждый чанк — отдельный запрос в батче: краткий пересказ + кандидаты в «решения» и «TODO» (structured output через tool use).
  - *reduce*: второй батч из одного запроса — собрать финальное саммари, дедуплицировать решения/TODO.
- Извлекаем три вида сущностей:
  1. **Саммари** — что произошло, по сценам.
  2. **Ключевые решения** — выборы партии, обещания NPC, изменившие мир факты.
  3. **TODO мастера** — реплики вида «о, эта абилка не работает, поправлю к следующей сессии».
- Финальную **вычитку и вписывание в канон** (вики-ссылки, обновление таймлайна, Open_Questions) делаем вместе в Cowork-сессии — скрипт готовит черновик, а не трогает лорные файлы сам.

### 5. Запись в волт
- `05_Campaign/Sessions/Session_NN.md` — заметка сессии (шаблон добавим в `00_Meta/Templates/`): frontmatter (дата, арка, участники), саммари, решения, яркие цитаты с таймстемпами.
- `05_Campaign/Session_TODOs.md` — единый файл: чекбоксы, у каждого пункта ссылка на `[[Session_NN]]` и таймстемп.
- `05_Campaign/Transcripts/` — сырые транскрипты.
- В конце — `git commit` (pre-commit схему сессионных заметок не проверяет — `arcs:` обязателен только у npc/location; шаблон сделаем совместимым).

## Технологии

| Слой | Выбор |
|---|---|
| Язык / окружение | Python 3.11+, venv в `00_Meta/scripts/session_pipeline/` |
| Аудио | ffmpeg (CLI, через subprocess) |
| STT | `assemblyai` SDK, Universal-2, ru |
| LLM | `anthropic` SDK, Message Batches API, Claude Sonnet |
| Структурные ответы | tool use (JSON schema) + pydantic-валидация |
| Конфиг | `players.yaml` + `.env` (ключи; в `.gitignore`) |
| Запуск | `python process_session.py path/to/craig.zip --session 12` |

## API-ключи и аккаунты

- **AssemblyAI** — ключ с [assemblyai.com](https://www.assemblyai.com/) (dashboard → API key). Оплата по факту, ~$0.1–0.4/час аудио (уточнить актуальный тариф при имплементации).
- **Anthropic API** — ключ с [console.anthropic.com](https://console.anthropic.com/). Отдельный от подписки Claude, биллинг по токенам.
- **Craig** — ключ не нужен, только инвайт бота на сервер.

## Оценка стоимости (сессия ~4 ч, 5 участников)

- STT: 20 ч сырого аудио → после вырезания тишины ~5-6 ч → **~$1-2**.
- LLM (Sonnet, batch): ~150-200k in / ~10k out → **~$0.3-0.6**.
- Итого **< $3 за сессию**.

## Порядок реализации

1. Скелет скрипта + `players.yaml` + распаковка Craig-архива.
2. ffmpeg-препроцессинг с картой таймстемпов (юнит-тест на восстановление оффсетов).
3. Интеграция AssemblyAI + word_boost из волта.
4. Merge в хронологический транскрипт.
5. Batches-этап: промпты map/reduce + структурные схемы.
6. Шаблон Session-заметки, запись в волт, git.
7. **Пилот на тестовой записи** (созвон на 20-30 минут с парой друзей) до первой реальной сессии.
